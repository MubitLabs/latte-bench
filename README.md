# Mubit · Coffee Workstation

A single playable, block-styled 3D coffee workstation. Vanilla JavaScript, Three.js, Rapier, and Bun. No React. No preset latte drawing, target-matching score, side-by-side dashboard, or illustrative cost race.

## Run

```sh
bun install
bun run dev
```

Open http://127.0.0.1:3000. The simulation works locally without an API key. A WebGL + WebAssembly capable browser is required.

## Operate the station

1. **Grind / 1:** grind an 18 g dose. The green/red physical buttons on the machine and grinder are clickable as well as the bottom console.
2. **Extract / 2:** extract a 36 ml shot. The cup then moves to the pouring mat.
3. **Steam / 3:** turn steam on, then off at 55–65°C. Milk scorches above 75°C.
4. **Pick up / 4:** pick up the pitcher. Drag in Cup View or use WASD / arrows to move it. Q/E change height. The tilt slider controls flow. The rim limits how low the spout can reach while the cup is empty; the height readout shows the effective height and marks this limit.
5. **Hold Space / Hold to pour:** milk falls from the spout. Pour high to mix, low to deposit foam. Moving the pitcher displaces the evolving surface. Missing the rim spills milk. The cup can overflow.
6. **Serve / 5:** finish the cup. **New cup** resets the task.

The camera button cycles views. The cube button drops a dynamic sugar cube with gravity, rotation, friction, and collisions. Sound is opt-in. The Session panel exposes real measurements and exports observations/actions as JSON.

**Agent → Local demonstration** operates these controls through a scripted sequence, including a low, wiggling pour and a pull-through. It is labeled as a local demonstration, not an AI model. The resulting art is generated by the fluid field, not a stored picture. Any manual control takes over from an automated run.

## Physics

- [Rapier](https://rapier.rs/docs/user_guides/javascript/rigid_bodies/) handles rigid bodies: a fixed counter/floor, kinematic cup and pitcher, and dynamic sugar cubes. Kinematic tools are positioned by the controls; their movement can push dynamic props. They are not force-controlled hands and do not automatically stop against every fixed shape.
- Milk is emitted as droplets with volume, initial velocity, and gravity. Droplets deposit only upon impact, or count as spilled outside the circular cup. Milk volume is conserved across pitcher, airborne drops, cup, and spill.
- The surface uses a 96×96 circular grid. Semi-Lagrangian velocity/foam advection, pressure projection, boundary constraints, and impact momentum evolve the field. Higher drops have reduced surface deposition; lower drops leave more foam. Temperature influences foam quality. This is a stylized 2D incompressible surface approximation coupled to 3D trajectories, not PhysX, full 3D SPH, or a calibrated milk/coffee CFD model.
- The top-down view and the 3D cup render the same current fluid field. Coverage is a measurement, not a trained visual art score. There is no hidden ideal pour or automatic convergence.

## API agent

Copy `.env.example` to `.env`, add your actual credentials/model IDs, and restart Bun:

```dotenv
MUBIT_BASE_URL=https://api.mubit.ai/openai/v1/
MUBIT_API_KEY=your-key
MUBIT_MODEL=your-mubit-route
FRONTIER_MODEL=your-frontier-model
```

`MUBIT_BASE_URL` is the API prefix; `/chat/completions` is appended unless already present. Optional `FRONTIER_BASE_URL` and `FRONTIER_API_KEY` use a separate provider; otherwise both model choices use Mubit. `MUBIT_EXTRA_BODY` accepts a JSON object of documented gateway routing fields. Keys remain server-side. `.env` is ignored and cannot be served by the static file handler.

Choose **Agent → API agent → Route → Attempts → Start fresh attempt**. Select 1, 3, or 5 cups; each starts from a fresh simulation, including when the previous cup was served. One controller runs at a time, with at most 32 requests per cup (up to 160 for five cups). Every request includes actual simulation state, the recent action history from this cup, and a 10×10 text representation of foam density. The model returns one bounded action, for example:

```json
{"command":"pour","x":0.2,"z":0.1,"height":15,"tilt":65,"duration":1}
```

Commands: `grind`, `extract`, `steam`, `pickup`, `move`, `pour`, `stop`, `serve`, `reset`. Coordinates are normalized to cup radius; `x,z ∈ [-1.4,1.4]`, height is 10–220 mm, tilt is 0–85°, duration is 0.05–5 seconds. Actions are validated before execution. Simulation time pauses while a model request is pending, so network latency cannot burn milk or change the observation. Timed API pours stop before the next observation/request. An error stops the batch; takeover stops pouring and steaming. An already accepted provider request may still be billed after browser cancellation.

The **Practice Log** shows thinking time, the current action, calls, reported tokens, and returned model IDs. **Attempts** compares the first and latest cup images and lists measured spill, milk temperature, outcome, and calls. The last 30 completed/stopped API attempts, including traces and responses, persist in browser local storage and can be exported. These are independent trials: local history is not injected into later runs. A served cup is not a visual art-quality verdict.

Actual reported tokens and optional `usage.cost` appear in Session and exported attempts. Configure that field only if your gateway reports cost in USD. No inferred prices, automatic training, or owned-model creation is claimed. The UI explicitly labels adapter status as unverified: this integration has no documented training submission/status endpoint, threshold, or adapter identity signal. A returned model ID alone does not prove adapter activation. If both routes have the same gateway/model, the UI identifies that configuration. The gateway's training/trace-ingestion lifecycle still needs its documented contract.

## Computer-use interface

All essential controls are accessible HTML buttons/sliders with keyboard equivalents, suitable for a computer-use agent. The browser also exposes `window.coffeeWorkstation`:

```js
coffeeWorkstation.observe();  // physical task state, current controls, surface grid
await coffeeWorkstation.act({ command: 'grind', duration: 2.2 });
await coffeeWorkstation.act({ command: 'extract', duration: 4.2 });
coffeeWorkstation.capture();  // PNG data URL of the actual fluid surface
coffeeWorkstation.exportTrace(); // timestamped observations + actions
coffeeWorkstation.reset();
```

The bridge uses the same action validation as the UI and takes over from automated controllers. It exposes no credentials. It is a browser API, not a remote-control HTTP server. Session traces last for the current cup until exported; API attempt history is additionally persisted as described above. Neither is trained model weights.

## Verification and build

```sh
bun test
bun run build
```

Tests cover preparation gates, command bounds, conservation of milk, spatial deposition, height-dependent mixing, thermal failure, solver bounds, and the server adapter against a local mock provider. The static `dist/` build runs the workstation and local demonstration. API agents require the Bun server. Browser bundles rebuild when source files change; reload the page to see changes.
